Un **dominio es atomico** si los elementos del dominio se consideran unidades indivisibles. Por ejeplo, suponga que la taba **profesor** tiene un atributo numero_telefono, que puede almancenar un cojunto de numeros de telefono correspondientes al profesor.
Entonces, el dominio de numero_telefono no seria atomico, ya que un elemento del domnio es un conjunto de numeros de telefono, y tiene subpartes, que son cada uno de los numeros de telegono individuales del conjunto

# Estructura del Modelo Relacional
1. Relaciones (tabas)
	- Representan entidades o asociaciones
	- Cada tabla tiene un nombre unico
2. Tuplas (filas)
	- Cada fila corresponde a un registro unico
	- Ejemplo: un alumno en una tabla de Estudiantes
3. Atributos (columnas)
	- Representan las caracteristicas de la entidad
	- Ejemplo: Matricula, Nombre, Carrera
4. Dominios
	- Conjunto de valores permitidos para un atributo
	- Ejemplo: El doinio de edad son numeros enteros positivos

# Claves del Modelo Relacional
Clave Primaria (PK)
- Identifica de manera unica cada fila
- Ejemplo: Matricula de Estudiantes
Clave Foranea (FK)
- Es un atributo que establece una relacion con otra tabla
- Ejemplo: ID_Carrera en Estudiantes Referencia a Carreras
Clave Candidata
- Conjunto minimo de atributos que pueden ser PK
Clave compuesta
- Una PK formada por dos o mas atributos

# Integridad en el Modelo Relacional
Para garantizar datos correctos, el modelo define tres tipos de integridad:
1. Integridad de Entidad: Ninguna PK puede ser nula
2. Integridad Referencial: Los valores de una FK deben existir en la tabla referenciada
3. Integridad de Dominio: Los valores deben pertenecer al dominio definido
